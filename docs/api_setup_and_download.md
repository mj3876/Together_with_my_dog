# API 인증키 발급과 숙박비율 다운로드

확인일: 2026-09-14. 아래는 공개된 공식 안내와 현재 작성한 코드에 근거한 절차입니다. 로그인 이후 화면이나 실제 다운로드 파일을 직접 검증한 상태는 아닙니다. 로그인 뒤 메뉴 이름이 조금 다르면 '활용신청 현황', '인증키', '숙박방문자 비율 추이' 항목을 기준으로 찾습니다.

## 현재 파일과 진행 상태

| 파일 | 역할 | 상태 |
|---|---|---|
| `fetch_tourapi.py` | 공식 방문자 API 연결 확인, 하루 자료 조회, 12개월 수집 및 월별 합산 | 작성·오프라인 테스트 완료, 실제 수집 미검증 |
| `configure_tourapi_key.py` | 키를 화면에 표시하지 않고 `.secrets/tourapi.key`에 저장 | 키 발급 후 사용자 터미널에서 실행 |
| `select_development_region.py` | 방문·숙박 입력 검사, 세 가중치 점수와 순위 산출 | 가상 자료 검증 완료 |
| `docs/tourapi_openapi.json` | 공공데이터포털 공개 페이지에 포함된 공식 Swagger 명세 사본 | 공식 문서에서 확보 |
| `tests/test_tourapi.py` | 인증 오류, 페이지 수집, 누락 일자, 월별 합산 등 | 18개 오프라인 테스트 통과 |
| `tests/test_region_selection.py` | 점수 산식, 동점, CSV 입력 검사 등 | 20개 테스트 통과 |

| `region_monthly.csv` | 방문·숙박을 합친 최종 입력 | 헤더만 있음 |

현재 실제 관광 데이터 다운로드는 0건입니다. 추가 네트워크 권한을 이용하는 두 번째 연결 시도는 취소되어 실행되지 않았습니다. 새 테스트에서는 실제 서버를 호출하지 않고 가상 응답을 사용했습니다.

## 1. 신청할 API

[한국관광공사_빅데이터_지역별 방문자수_GW](https://www.data.go.kr/data/15101972/openapi.do)

이 API의 현재 이름은 위와 같습니다. 과거에 '관광빅데이터 정보서비스'로 안내된 서비스입니다. 현재 공식 명세의 조회 기능은 아래 두 개이며, 숙박방문자 비율은 포함하지 않습니다.

- 시도: `https://apis.data.go.kr/B551011/DataLabService/metcoRegnVisitrDDList`
- 시군구: `https://apis.data.go.kr/B551011/DataLabService/locgoRegnVisitrDDList`

공식 페이지 기준 무료이며 개발계정은 자동승인, 운영계정은 심의승인입니다. 우선 개발계정으로 시작합니다. 필수 요청값은 `MobileOS`, `MobileApp`, `serviceKey`, `startYmd`, `endYmd`이고, 페이지 조회에 `pageNo`, `numOfRows`를 사용합니다. 지역 필터 요청 파라미터는 명세에 없으므로 API가 돌려준 행에서 코드로 선택합니다.

## 2. API 인증키 발급

1. 위 API 상세 링크를 브라우저에서 엽니다.
2. 공공데이터포털 계정으로 로그인합니다. 계정이 없으면 회원가입과 화면에서 요구하는 본인 확인을 직접 완료합니다. 데이터랩 웹사이트 로그인과 API 활용 승인은 별도의 절차입니다.
3. 제목이 **한국관광공사_빅데이터_지역별 방문자수_GW**인지 확인합니다.
4. **활용신청**을 누릅니다. 개발계정 신청 화면에서 요구하는 필수 항목을 입력합니다.
5. 활용 목적에는 실제 작업을 설명합니다. 예: '반려견 동반 여행 서비스 개발 후보 지역을 비교하기 위해 지역별 외지인 방문자 수를 수집하고 월별 관광수요를 분석합니다.' 해당 선택 항목이 있다면 개발/연구 목적과 맞는 것을 선택합니다.
6. 활용할 기능 선택란이 있다면 개발 범위에 맞는 시도/시군구 방문자 조회 기능을 선택합니다. 두 행정 단위 모두 검토할 계획이면 두 기능을 선택할 수 있습니다.
7. 이용 조건을 읽고 신청을 제출합니다. 이 API는 개발단계 자동승인으로 안내되지만 실제 상태가 **승인/활용중**인지 확인합니다.
8. **마이페이지 → 오픈API → 활용신청 현황**에서 신청한 API를 엽니다. 화면에 '개발계정' 또는 '개발계정 상세보기'로 표시될 수도 있습니다.
9. 인증키 항목을 확인합니다. 발급 버튼이 있으면 발급을 진행합니다. Encoding과 Decoding 두 가지가 보이면 **일반 인증키(Decoding)**를 복사하는 것이 이해하기 쉽습니다. 현재 코드는 두 표기를 모두 처리하도록 작성했습니다.
10. 키를 채팅에 붙여넣지 말고 아래 로컬 입력 절차를 따릅니다. 키만 발급받고 해당 API 활용 승인이 없으면 요청이 거절될 수 있습니다.

공식 절차 참고: [공공데이터포털 오픈API 활용신청·승인·인증키 안내](https://www.data.go.kr/ugs/selectPublicDataUseGuideMetView.do).

## 3. 키를 현재 프로젝트에 저장

프로젝트 폴더를 연 PowerShell 터미널에서 다음 ㅊ두 줄을 실행합니다. 현재 환경에서 확인한 Python 경로입니다.

```powershell
$pythonExe = 'C:\Users\ms840\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
& $pythonExe -X utf8 .\configure_tourapi_key.py
```

입력 안내가 나오면 복사한 키를 붙여넣고 Enter를 누릅니다. 화면에 입력 내용이 표시되지 않아도 정상입니다. 저장 성공 안내가 나오는지 확인합니다. 프로그램은 `.secrets/tourapi.key` 파일을 만들며 기존 키 파일을 덮어쓰지 않습니다. `.secrets/`는 `.gitignore`에 등록되어 있습니다. 파일은 로컬 평문이므로 공유하거나 배포하지 않습니다.

이 방법을 쓰는 실행 명령에는 `--key-file .\.secrets\tourapi.key`를 넣습니다. 환경변수를 선호하면 `TOURAPI_SERVICE_KEY`를 설정하는 방식도 지원합니다. 현재 프로젝트에 실제 키 파일을 생성하거나 키를 발급한 상태는 아닙니다.

## 4. 키 발급 후 API 자동화 실행 순서

먼저 한 날짜의 연결·인증을 확인합니다. 아래 날짜는 실행 형식 예시입니다. 해당 날짜의 실제 제공 여부는 인증 후 확인해야 합니다. `check`는 분석 파일을 저장하지 않습니다.

```powershell
& $pythonExe -X utf8 .\fetch_tourapi.py check --date 2025-01-01 --level sigungu --key-file .\.secrets\tourapi.key --output .\runs\api_check_after_key
```

연결이 확인되면 한 날짜의 모든 페이지를 내려받아 API의 지역 코드와 방문자 구분명을 확인합니다.

```powershell
& $pythonExe -X utf8 .\fetch_tourapi.py probe --date 2025-01-01 --level sigungu --key-file .\.secrets\tourapi.key --output .\runs\api_probe_01
```

성공하면 `available_regions.csv`, `manifest.json`, `raw/`가 생깁니다. 지역코드는 `available_regions.csv`, 외지인 구분명은 `manifest.json`의 `visitor_types`에서 확인합니다. **지역코드를 추측하거나 시군구명만 보고 같은 이름의 다른 지역과 혼동하지 않습니다.**

후보와 공통 기간이 확정되면 12개월을 수집합니다. 아래 `<후보코드1>` 등은 probe 결과로 바꿔야 하므로 그대로 실행하지 않습니다.

```text
python -X utf8 fetch_tourapi.py fetch --start 2025-01 --end 2025-12 --level sigungu --regions <후보코드1> <후보코드2> --visitor-type 외지인 --key-file .secrets/tourapi.key --output runs/api_visitors_01
```

실제 PowerShell에서는 위의 `python` 대신 `& $pythonExe`를 사용합니다. `--regions` 생략 시 해당 행정 단위 전체를 대상으로 처리하므로, 가이드의 후보 비교에는 확정한 후보 코드를 명시합니다. `--visitor-type`은 probe가 반환한 외지인 유형명과 정확히 맞춥니다.

수집은 월별 기간으로 요청하고 모든 페이지를 읽습니다. 각 지역의 월별 일자가 하나도 빠지지 않았을 때만 일별 방문값을 월 합계로 만듭니다. 매월 지역 코드·이름·유형이 같아야 합니다. `visitors_monthly.csv`와 요청 조건·원본 해시가 포함된 `manifest.json`, `raw/`를 저장합니다. 원본에는 전체 반환 지역/유형이 들어 있을 수 있고 분석 CSV는 선택한 후보/유형만 담습니다.

이 결과는 일별 방문자 합계이며 연간 고유 관광객 수가 아닙니다. API 월 합계와 데이터랩 월간 화면의 외지인 지표가 일치하는지는 첫 실제 자료에서 대조해야 합니다. 과거 기간이 API에서 제공되지 않거나 행정경계가 달라지면 기간·후보를 다시 검토해야 합니다. 이 제공 범위는 아직 실제 요청으로 확인하지 못했습니다.

실패 시 `manifest.json`의 `status`, `error_code`를 확인합니다. 인증 오류·네트워크 오류·빈 데이터·누락 일자는 성공으로 표시하지 않습니다. 원본 일부를 받은 뒤 실패할 수 있으며 이때 원본과 실패 기록만 남고 완성된 월별 CSV는 생성하지 않습니다. 자동 이어받기는 아직 없으므로 원인을 해결한 뒤 새 결과 폴더로 실행합니다.

## 5. 숙박방문자 비율 다운로드

이 단계에는 공공데이터포털 API 키가 아니라 **데이터랩 웹사이트 로그인**을 사용합니다. 아래 절차는 [데이터랩 지역별 관광 현황 공개 화면](https://datalab.visitkorea.or.kr/datalab/portal/loc/getAreaDataForm.do)의 메뉴·지표·다운로드 안내를 기준으로 작성했습니다.

1. 먼저 비교할 후보 목록과 공통 연속 12개월을 정합니다. 방문자 API와 숙박비율 양쪽에서 그 기간의 자료가 모두 확보되어야 합니다. 2025-01~2025-12는 예시이며 아직 확정 기간이 아닙니다.
2. PC 브라우저에서 [데이터랩 지역별 관광 현황](https://datalab.visitkorea.or.kr/datalab/portal/loc/getAreaDataForm.do)을 열고 로그인합니다. 메뉴로 이동한다면 **지역별 분석 → 지역별 현황 → 지역별 관광 현황**입니다.
3. 상단 **지역**에서 첫 후보를 선택합니다. 시군구 분석이면 시도와 해당 시·군·구를 정확히 선택합니다. 시도 분석이면 시도 전체 범위를 선택합니다. 모두 같은 행정 단위를 사용합니다.
4. **기준**을 **월간**으로 선택합니다.
5. 시작·종료를 확정한 연속 12개월로 설정하고 화면의 조회 기능으로 반영합니다. 차트의 실제 시작·종료 월이 선택한 조건과 일치하는지 확인합니다.
6. **숙박/체류시간** 탭을 엽니다.
7. **숙박방문자 비율 추이** 지표를 찾고 **외지인** 기준인지 확인합니다. 필요한 것은 각 월의 숙박방문자 비율 12개입니다.
8. 화면의 공식 **전체 다운로드**를 선택합니다. 개별 차트 다운로드가 제공되면 해당 지표를 받을 수도 있습니다. 다운로드 항목을 선택하는 창이 뜨면 숙박방문자 비율 추이를 선택합니다. 전체 파일만 제공되면 파일 안에서 해당 표를 사용합니다.
9. 파일 형식 선택에서 **CSV**를 우선 선택합니다. CSV가 제공되지 않는 항목이면 **EXCEL**로 내려받습니다. 다운로드 사유를 요구하면 실제 목적에 맞는 항목을 선택하고, 직접 입력란이 있을 때는 '반려견 동반 여행 서비스의 개발 후보 지역 비교 분석'처럼 적습니다.
10. 파일을 내려받아 프로젝트의 `data/raw/`에 보관합니다. 파일명 예시는 `<지역ID>_overnight_202501_202512.csv`입니다. 기간·확장자는 실제 파일에 맞춥니다. 원본 내용은 수정하지 않습니다.
11. 파일을 열어 지역명, 월간 기준, 외지인, 12개월, 비율 단위를 확인합니다. 연간 평균 하나만 있거나 다른 숙박 지표라면 월별 비율 추이를 다시 받습니다. 달이 가로 열에 있어도 괜찮습니다.
12. 나머지 후보에서도 같은 기간·필터·단위로 반복합니다. 후보 5곳이면 총 60개의 월별 숙박비율이 필요합니다. 실제 파일 수는 공식 다운로드의 묶음 방식에 따라 달라질 수 있습니다.
13. `data/raw/README.md` 양식에 조회 메뉴, 지역, 기간, 지표, 단위, 다운로드일, 원본 파일명을 기록합니다.

현재 실제 다운로드 파일을 보지 못했으므로 열 이름과 시트 배치는 확정하지 않았습니다. 원본을 확보한 뒤 분석용 파일에서 월을 `YYYY-MM` 행으로 정리합니다. 23.5%라면 최종 입력은 `23.5`입니다. 원본이 0.235라는 비율인지 0.235%인지 단위를 먼저 확인하고 변환합니다. 누락값은 0으로 넣지 않습니다.

## 6. 두 자료를 결합할 때

원본 파일을 보존한 채 `region_code + month`가 같은 방문값과 숙박비율을 1:1로 결합합니다. 시도·시군구 구분과 기간이 같아야 하며, 이름만으로 합치지 않습니다. 후보의 코드 매핑은 API probe 결과와 원본 지역명을 대조합니다.

최종 입력 `region_monthly.csv`의 헤더:

```text
region_code,region_name,region_level,month,visitors,overnight_pct,visitor_source,overnight_source
```

실제 숙박 파일의 배치를 아직 확인하지 못해 자동 정규화·결합은 현재 구현하지 않았습니다. 숙박비율 확보·원본 대조·결합이 끝나야 기존 점수 계산 스크립트를 실행할 수 있습니다. 반려견 동반 시설 부족은 이 두 지표만으로 검증되지 않습니다.
